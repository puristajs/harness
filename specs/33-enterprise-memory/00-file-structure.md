# File and ownership structure

## Harness repository

- `packages/harness/src/identity/` owns `HarnessIdentity`, binding, normalization, and safe identity fingerprints shared by session storage and memory.
- `packages/harness/src/ports/memory/` owns public contracts, the final core orchestrator, facade, validation, telemetry, search fusion, and summary behavior.
- `packages/harness/src/memory/in-memory/` owns the dependency-free reference engine.
- `packages/harness/src/storage/` stores bound session identity and fixes the existing SQLite message `runId` persistence gap.
- `packages/harness/src/testing/` owns `fakeMemoryEngine`, deterministic fixtures, and `memoryEngineContract`.
- `packages/harness-memory-sqlite/` owns the local SQLite driver boundary, schema, FTS5 queries, optional sqlite-vec loading, engine implementation, runtime-matrix tests, and README.
- `packages/harness-memory-postgres/` owns PostgreSQL options, migrations, SQL, engine implementation, package tests, and README.
- `packages/harness-memory-redis/` owns Redis options, key/index layout, scripts, engine implementation, package tests, and README.
- `packages/harness-memory-nats/` owns the current NATS v3 client lifecycle, JetStream KV bucket/key layout, compare-and-set writes, bounded enumeration, lazy expiry, engine implementation, package tests, and README.
- `examples/enterprise-memory/` owns a runnable provider-neutral example using the fake model provider and in-memory engine; vendor examples remain in package READMEs to avoid service dependencies in the default example suite.
- `docs/guides/memory.md`, `docs/reference/public-api.md`, `docs/operations/runbook.md`, and `docs/security/security-model.md` own Harness documentation.

The PostgreSQL package's PGlite and pgvector test fixture remains private test source and development dependencies. No `@purista/harness-memory-pglite` package or testing re-export is created.

## PURISTA repository

- `packages/core/src/AgentQueueBuilder/` owns runtime option typing and propagation of PURISTA message `tenantId` and `principalId` into the Harness session binding.
- `examples/agent-example/` contains one attached-agent memory example using the default engine and fake model testing path.
- `web/src/content/handbook-cards/harness/agents-workflows-storage.mdx` links the concepts without duplicating the developer guide.
- `web/src/content/handbook-cards/harness/memory.mdx` is the detailed developer guide for setup, scope, search, summaries, tests, security, operations, and migration.
- `web/src/content/handbook-cards/harness/adapters-durability-reference.mdx` carries the capability/runtime matrix.
- `web/src/pages/harness/memory.astro` presents architecture and business value for architects and CTOs.
- `skills/purista/references/05-ai-harness-runtime.md` and the canonical AI Harness skill mirror the implemented names and constraints.

Existing `packages/redis-state-store/`, `packages/nats-state-store/`, and `packages/dapr-sdk/` remain general PURISTA components. This plan does not modify their public contracts, move them, or make them dependencies of Harness packages.

## Generated outputs and entrypoints

TypeScript declarations are generated by each package build from owner source. There is no duplicate generated model, OpenAPI, GraphQL, protobuf, event, or database client. SQL migrations are versioned package assets, not generated output. Public exports originate only from each owning package root; engine packages do not forward core types. Package metadata, root workspace inventory, docs inventory, and release checks list all four optional memory-engine packages.

## Migration ownership

The clean break deletes the sandbox-backed memory implementation and `user` vocabulary after all consumers move. Migration guidance maps `sandboxMemory()` to the default in-memory engine or an engine package, `user()` to `principal()`, and string model aliases to `model.<alias>` references. SQLite memory uses its own `.purista/memory.sqlite` example file and table namespace; it does not silently reuse the HarnessStorage SQLite file. No deprecated source remains after the migration ticket.
